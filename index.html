Understand QUEUESKI

A concise reviewer of the student portal, its main features, and how its parts work together.

1. Technologies

HTML

Structures the page: headings, forms, buttons, tables, and content.

CSS

Controls appearance, spacing, colors, layout, and responsive design.

JavaScript

Adds interaction, such as menus, search, theme switching, and page updates.

PHP

Runs server-side logic and handles requests from the website.

MySQL

Stores student details and request records in database tables.

2. Main Modules

Student Portal

Lets students sign in, view their portal, and submit or track requests.

Accounting

Provides the area for accounting-related requests and their processing status.

Registrar

Handles registrar requests, including tracking whether documents are pending, in progress, or completed.

Admin Dashboard

Gives authorized staff access to the relevant modules and request records.

3. Project Files

Separating files makes the project easier to maintain. Each file type has a specific responsibility.

Example folder structure
queueski/
├── api/          # Server-side request handlers
├── components/   # Reusable page components
├── config/       # Database/configuration settings
├── css/          # Stylesheets
├── images/       # Images and icons
├── js/           # JavaScript files
├── pages/        # Website pages
├── vendor/       # Installed libraries
└── index.php     # Main entry point (if used)
  • HTML/PHP pages: page structure and server-rendered content.
  • CSS files: visual design only.
  • JavaScript files: browser-side interactions.
  • API files: receive and process requests between the browser and server.
  • Configuration files: shared settings, such as database connection details.

4. Database Basics

A database stores information in tables. A table contains columns (fields) and rows (records).

TablePurposeExample fields
studentsStores student account information.Student number, name, email
registrar_requestsStores requests sent to the Registrar.Request ID, student number, request type, status

Remember: a primary key uniquely identifies a record. A foreign key can connect a record to another table, such as linking a request to a student.

5. How the Workflows Go

Student request

  1. The student signs in.
  2. The student submits a request.
  3. The system saves the request in the database.
  4. Staff review and update its status.
  5. The student checks the updated status.

Request status

  • Pending: waiting to be processed.
  • In Progress: staff are working on it.
  • Completed: processing is finished.

Email notification demo

When a request is marked completed, the system can notify the student that the requested document is ready for claiming. A real email feature needs a configured mail service and valid recipient address; a demo message alone does not send an email.

6. API Basics

An API endpoint is a server URL that the website calls to perform an action or retrieve data.

Typical request flow

Browser → API/PHP → MySQL → API response → Browser

The browser sends a request. The server validates and processes it, may read or update the database, then returns a response.

Common HTTP methods

  • GET — retrieve information.
  • POST — submit information or create a record.
  • PUT/PATCH — update information.
  • DELETE — remove information.

7. Programming Concepts to Know

Frontend vs. backend

Frontend: what the user sees and interacts with. Backend: server-side processing, validation, and database operations.

CRUD

  • Create: add a record.
  • Read: view or retrieve a record.
  • Update: change a record.
  • Delete: remove a record.

Validation and security

  • Validate user input on the server, not only in the browser.
  • Use prepared statements for database queries.
  • Store passwords securely using password hashing.
  • Check permissions before allowing staff-only actions.
  • Do not expose database passwords or private configuration details.
